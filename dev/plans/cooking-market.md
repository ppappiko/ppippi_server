## A. Pet stand (PET_MARKET)
Server dev/pipi-rpg/src/PipiLife.java (~1578-1638 today: sells stored pets to the server at a fixed level price) + client dev/pipi-travel/src/PetMarketScreen.java.
- Owner view (right-clicking your own stand): 5 listing rows. Put a pet from your pet storage into an empty row (pick from your stored pets list in the screen), type a price (number input in the client, 1..100,000,000), press 판매 시작 → listed. A listed pet is locked: it can't be placed in facilities, moved, released, sold elsewhere (keep it in storage data but flagged, or move it into the listing — your choice, but it must never be duplicated or lost). 판매 중지 on a row returns it to storage. Proceeds of sold pets accumulate on the stand; 대금수령 pays them out as gold.
- Buyer view (right-clicking someone else's stand, or a stand while not the owner): shows the owner's name and the 5 listings with prices; 구매 buys if the buyer has the gold and a free pet storage slot: gold moves to the owner's proceeds, the pet moves to the buyer's storage. Owner offline must work (data-based). Messages in Korean, notify the owner if online.
- Keep the old instant sale to the server at the fixed level price as a secondary button "상점에 바로 판매" in the owner view.
- Persist listings and proceeds in the plugin data. Chest-menu protocol of your choice (follow the existing PetMarketScreen/PetStorageScreen patterns of commands `pipilife ...` + chest slots); keep a usable plain-chest fallback for basic actions if simple.

## B. Cooking table (COOKING_TABLE)
Facility COOKING_TABLE exists and is placeable; today right-click says "기능은 준비 중입니다" (Facility.comingSoon()). New server class dev/pipi-rpg/src/Cooking.java, hook it in where comingSoon is handled; new client dev/pipi-travel/src/CookingScreen.java registered in PipiTravel.java (title mapping + every instanceof exclusion list, like AlchemyScreen); new mod items in dev/pipi-facilities.
- Mod items (stack 64, ko_kr/en_us names in Korean, item models, 32x32 placeholder textures generated by a node script dev/art/make-cooking-placeholders.mjs — zlib PNG, python is broken): seasonings salt 소금, sugar 설탕, pepper 후추, soy_sauce 간장; dishes hearty_salmon_stew 든든한 연어 양배추찜, hearty_carrot_soup 든든한 당근 수프, hearty_veggie_salad 든든한 채소 샐러드, failed_dish 정체불명의 요리.
- Ingredients = any of: 양배추 (mod cabbage), 당근 (mod pet_carrot), 짚 (mod straw), 생 연어 (mod raw_salmon), 감자 (vanilla POTATO), 양배추 씨앗 excluded. Seasonings bought in the existing shop (TownSystems SaleSpec list) for now: 소금 200, 설탕 200, 후추 300, 간장 500 gold (the user's "요리 상점 조수" NPC comes later).
- Recipes are data in plugins/PipiLife/cooking.yml (created with defaults if missing, Korean comments): each has 3 ingredients (order-independent, duplicates allowed), 1 seasoning, result dish id, and effect: `pet-food: <포만감>` and/or `buff: {type: <health|strength|speed|regeneration>, amplifier, seconds}`. Defaults: 연어 양배추찜 = 생 연어 + 양배추 + 감자 + 소금 → pet food 60; 당근 수프 = 당근 + 당근 + 감자 + 설탕 → player buff regeneration I 60 s and pet food 40; 채소 샐러드 = 양배추 + 당근 + 짚 + 후추 → player buff speed I 180 s. Dish pet food values join the existing `pet-food` table logic (feeding pets accepts dishes with their value); eating a buff dish (right-click use; mod items aren't vanilla food, so handle PlayerInteract with the item in hand, consume 1, apply the potion effect) applies its buff.
- Flow: the player picks 3 ingredients + 1 seasoning from their bag in the screen (click an ingredient in the 식재료 panel to fill the next box, click a box to clear it), then 요리하기 starts the mini-game (client-side): a ladle marker moves up and down along the vertical gauge (speed rises slightly each pass); a green zone of random position covers about 20% of the height; the player presses the left mouse button or space to stop; inside the green zone = success. The client sends the result (`pipilife cook <ingredient ids...> <seasoning> <success 0|1>`) — server validates the player owns the items, consumes them, and: success + matching recipe → the dish (and the recipe is recorded in the player's 요리 수첩 if new: message "새 레시피를 배웠습니다: <요리>"); success + no matching recipe → 정체불명의 요리 (pet food 5); failure → 정체불명의 요리. Anti-abuse: a minimum interval of 3 s between cooks per player server-side.
- 요리 수첩 (left side of the screen, a list of learned recipes): clicking a learned recipe auto-fills its ingredients if the player has them, and those cooks get a wider green zone (35%) ("비교적 간편하고 빠르게").
- Button text "재료 부족" (disabled) when boxes aren't all filled or the player lacks items, otherwise "요리하기".
