## A. Residence chests in crafting
When a player crafts at the crafting station (TownSystems recipe crafting: hasIngredients / ingredientCount / consume paths used by the crafting station and the craft screen's ingredient counts), ingredients count from the player's bag PLUS every chest/trapped chest/barrel (real containers only — not facility marker blocks; check how stations use BARREL at PipiLife ~763) located inside the residence plot the player owns (village world, plot bounds = the plot area around its centre; find the plot size used by plot claiming/protection). Consumption takes from the bag first, then from those chests. Only while the player owns a plot; if not, bag only. The craft screen's "have/need" numbers include chest contents. Don't apply it to other systems (강화, 인챈트, shop, upgrades) unless they share the same helper — if they do, add a flag so only crafting uses chests. Mention in the recipe/ingredient lore "거주지 상자 포함".

## B. Warp stones (server + client)
- Mod block `warp_stone` (see C). Admin commands (op / pipilife.admin): `/pipilife warp create <id> <category> <name...>` places a warp stone on the block the admin is standing on (at their feet) and registers the waypoint (world, x, y, z, facing, category, name); `warp remove <id>` (removes block + entry), `warp list`, `warp rename <id> <name...>`, `warp category <id> <category>`, `warp move <id>` (to current position). Stored in plugins/PipiLife/warps.yml. Category "마을" = village waypoints: unlocked for everyone by default. Every other category needs activation: the first right-click on that stone activates it for that player ("웨이포인트를 활성화했습니다: <이름>") and stores it per player.
- Survival players can't break warp stones (cancel), explosions/pistons can't affect them.
- Right-clicking a warp stone (after activation if needed) opens a chest menu titled `삐삐서버 · 웨이포인트` for the client screen. Protocol: one slot per waypoint (up to 45, slots 0..44), item = a marker, name = waypoint name, lore line 0 = `wp:<id>|<category>|<world>|<x>|<z>|<unlocked 0/1>|<here 0/1>`; slot 49 = home button (BED, name "내 거주지", lore "home"); slot 53 = close. Clicking a waypoint slot (or command `pipilife warp go <id>`) teleports to just in front of that stone (safe spot, face away from the stone) if unlocked; locked ones say "아직 활성화하지 않은 웨이포인트입니다."; `pipilife warp home` = same as `/pipilife home`. 3 s cooldown, blocked while the player is in combat if the plugin tracks combat; works across worlds (load the world via VillageMaps.open if needed).
- Client WarpScreen (new, registered in PipiTravel.java like the other screens incl. all instanceof exclusion lists): layout like the reference. Left: map panel (about 2/3 width) with a parchment look drawn in code (beige fill, darker border, faint grid lines, an original compass rose drawn from lines/triangles, a few soft cloud blobs) and an area dropdown at top-left listing the worlds present in the waypoint data (show friendly names: village → "마을", world → "야생", other world names as-is); the map shows the waypoints of the chosen world placed by their x/z scaled to fit the bounding box of that world's waypoints (with padding; a single waypoint is centred); each waypoint drawn as a small cyan crystal icon (drawn shapes) on a dark pedestal — locked ones greyed with a lock mark, the stone you're at outlined; hovering shows the name; the selected one shows a name label under it. Home button (house icon) at the map's top-right sends the home command. Right: category list (collapsible headers like "마을 ∨", entries "• <name>", selected highlighted, locked entries muted with 🔒-like mark). Selecting an entry (map or list) selects it; clicking the selected one again or a "이동" button warps. Esc closes.

## C. Warp stone model (mod)
Register block `warp_stone` (with BlockItem so admins can also place it by hand; no loot, strength like obsidian-ish but the plugin protects it) in dev/pipi-facilities. A 3D JSON block model about 2 blocks tall (elements may extend to y=32): a dark stone pedestal (wide base 12x3x12, narrower column 8x4x8, top plate 10x2x10) and above it a floating cyan crystal: an elongated faceted gem made of stacked boxes forming a bipyramid silhouette (widths about 2,4,6,8,6,4,2 going up, the middle tallest), two of the middle layers rotated 45° on the Y axis (rotation origin at the centre) to suggest facets; textures 16x16 generated by a node script dev/art/make-warp-stone.mjs (zlib PNG; python is broken, don't use it): crystal_cyan with light/dark diagonal bands (#bff6ff, #5fd6e6, #2a9fb5, #17707f), pedestal_stone (dark slate #2e3440/#3b4252 with cracks). Non-occluding, cutout render type, light emission 7. Blockstate with 4 facings is optional. Names: 워프석 in ko_kr and en_us.
